# Выездная кастом-зона — Pinhead Studio

Готовый статический лендинг (десктоп + мобильная адаптация) по дизайн-макету
из `design/`. Открывается как обычная страница и разворачивается на Vercel
без дополнительной сборки.

## Структура

```
index.html      — разметка страницы
styles.css      — стили (адаптив: <768px мобильный, 768–1023 планшет, ≥1024 десктоп)
script.js       — интерактив: меню, чипы формата, маска телефона, валидация,
                   отправка формы, FAQ, аналитика, UTM/сессионный черновик
api/lead.js     — serverless-функция Vercel, принимает заявку с формы
assets/         — логотип, иконки, фото (webp + jpg фолбэк), шрифты
design/         — исходные материалы дизайнера (референс, не трогать в проде)
```

## Локальный запуск

Статику можно открыть прямо файлом в браузере, но для работы формы (запрос
к `/api/lead`) нужен локальный сервер:

```bash
npm run dev
# либо
npx vercel dev
```

## Деплой на Vercel

1. Запушить ветку в GitHub.
2. Импортировать репозиторий в Vercel — Framework Preset: **Other**,
   Build Command и Output Directory можно оставить пустыми (сайт статический,
   `api/lead.js` Vercel подхватит автоматически как serverless-функцию).
3. (Опционально) добавить переменную окружения `BITRIX_WEBHOOK_URL` — входящий
   вебхук Bitrix24 (например `https://your.bitrix24.ru/rest/1/xxxxxxxx`).
   Без неё форма всё равно работает и возвращает успех, но заявка только
   логируется — для реальных лидов нужен вебхук.

## Что уже сделано по ТЗ (`design/README.md`)

- Адаптивная вёрстка от 390 до 1440+ px.
- Форма: 9 полей, чипы формата (одиночный выбор), маска телефона,
  валидация телефона/email/Telegram, чекбокс согласия, состояния
  idle/submitting/success/error, honeypot + временная отсечка от спама,
  черновик в `sessionStorage`.
- Сбор UTM-меток, Client ID Метрики (`ym(...,'getClientID')`),
  Roistat-визита, referrer, `page_url` — передаются в `/api/lead`.
- FAQ на нативных `<details>`, плюс/минус переключается через CSS.
- Аналитические события (`page_view`, `click_calc`, `select_format`,
  `form_start`, `form_submit_success`, `click_phone`, `click_messenger`,
  `click_catalog`) пушатся в `window.dataLayer` и (если задан
  `window.YM_COUNTER_ID`) в Яндекс.Метрику.
- SEO: title/description/OG, JSON-LD `Service`, один `<h1>`, семантические
  секции, alt у всех фото, `fetchpriority="high"` на фото первого экрана,
  `loading="lazy"` — ниже.
- Изображения пережаты и отданы в WebP с JPEG-фолбэком через `<picture>`.

## Что осталось доделать (см. также `design/README.md` → Open Questions)

- Подключить реальный `BITRIX_WEBHOOK_URL` и (при необходимости) капчу.
- Вписать реальный ID Яндекс.Метрики: `window.YM_COUNTER_ID = XXXXXXXX`
  и подключить сам счётчик метрики в `<head>`.
- Заменить шапку/футер на компоненты из существующего сайта pnhd.ru,
  если этот лендинг будет вливаться в основной Next.js-проект, а не жить
  отдельным сайтом на Vercel.
- Финальные фото/видео первого экрана, кейсы с текстом, юридические тексты
  политики конфиденциальности.
- Проверить лицензии на веб-использование TT Bluescreens и Heading Pro
  перед публичным релизом.
